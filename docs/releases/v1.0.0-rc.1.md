# Mihoto v1.0.0-rc.1 release candidate

`v1.0.0-rc.1` is the first release candidate for Mihoto 1.0. It marks the
intentional compatibility boundary from per-user Mihoro to a root-owned,
systemd-only Mihoto installation.

## Highlights

- Four supported artifacts: `x86_64-unknown-linux-gnu`,
  `x86_64-unknown-linux-musl`, `aarch64-unknown-linux-gnu`, and
  `aarch64-unknown-linux-musl`.
- Root-owned configuration in `/etc/mihoto.toml`, Mihomo data in `/etc/mihomo`,
  binaries in `/usr/local/bin`, and system services/timers in
  `/etc/systemd/system`.
- TUN-ready `mihomo.service` with the required network capabilities.
- Verified installer and self-updater: exact version selection, `SHA256SUMS`,
  archive validation, smoke test, and atomic replacement.
- GitHub build attestation/provenance for the immutable release artifacts.

## Installation and verification

Install the RC explicitly:

```sh
curl -fsSL https://raw.githubusercontent.com/Pectics/mihoto/main/install.sh \
  | sudo sh -s -- --version v1.0.0-rc.1
```

After downloading the matching archive and `SHA256SUMS`, run:

```sh
sha256sum --check SHA256SUMS
gh attestation verify mihoto-v1.0.0-rc.1-x86_64-unknown-linux-gnu.tar.gz \
  --repo Pectics/mihoto
```

The release remains a prerelease until the real installation, TUN, reboot,
failure-recovery, uninstall, purge, and cleanup acceptance record is complete.

## Migration and removal

Mihoro installations are not migrated automatically. Stop and back up the old
user-level installation manually before initializing Mihoto. Plain `uninstall`
removes service and timer units but retains state for reinstall; `uninstall
--purge --yes` removes Mihoto-managed state deliberately.
