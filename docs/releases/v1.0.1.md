# Mihoto v1.0.1

Mihoto v1.0.1 publishes the local Mihomo configuration overlay work on top of
the v1 systemd contract. The release keeps remote subscription-owned dynamic
collections intact while allowing sparse, typed local configuration for stable
Mihomo settings.

## Highlights

- Sparse TOML-to-YAML overlay semantics: omitted fields preserve the remote
  value, objects merge recursively, and explicitly provided arrays replace the
  remote array, including an empty array.
- Strongly typed local support for general settings, DNS, hosts, sniffer, TUN,
  listeners, NTP, experimental, Geo data, UI, and other stable non-dynamic
  Mihomo settings.
- Complete local TUN examples including stack, routes, DNS hijack, interface,
  UID, MTU, and GSO-related settings.
- Controlled native-key `extra` support for non-dynamic fields that are not yet
  modeled, with dynamic collections and duplicate/conflicting keys rejected.
- Expanded unit, property-based, CLI-contract, YAML fixture, and integration
  coverage for configuration preservation, validation, rollback, and TUN
  behavior.

## Install and verify

```sh
curl -fsSL https://raw.githubusercontent.com/Pectics/mihoto/main/install.sh \
  | sudo sh -s -- --version v1.0.1
```

Each release workflow produces four target archives, `SHA256SUMS`, and GitHub
build provenance. Verify a downloaded archive with:

```sh
sha256sum --check SHA256SUMS
gh attestation verify mihoto-v1.0.1-x86_64-unknown-linux-gnu.tar.gz \
  --repo Pectics/mihoto
```

## Configuration boundary

See [the Mihomo support matrix](../mihomo-config-support.md) for the complete
local field list, sparse merge rules, dynamic collection boundary, and the
relationship between Mihoto's UI/Geo management and Mihomo's native fields.

The root-owned systemd service remains the supported runtime. Full-host TUN
requires a standalone DNS configuration and working DNS-hijack settings in
addition to the TUN section.

## Migration and removal

Mihoro installations are not migrated automatically. Plain `uninstall` retains
Mihoto/Mihomo state and binaries, while `uninstall --purge --yes` removes the
Mihoto-managed persistent state.

The final release audit records the actual automated gates and isolated
systemd/TUN host acceptance. Release artifacts and attestation are generated
by the tag workflow after those gates pass.
