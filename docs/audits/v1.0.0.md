## Physical-host result

The Ubuntu 26.04 x86_64 `pectos` run passed the repository systemd and TUN
harnesses, init and idempotent init, permissions and capabilities, reboot
restoration, component updates, apply, timer execution, recovery, and final
host cleanup.

It failed the original candidate because:

1. The GUI-exported one-node profile had no standalone DNS settings and did
   not establish the requested Japanese proxy exit.
2. A YAML-valid but Mihomo-invalid update replaced the working configuration,
   returned success, and caused a systemd restart loop.

The first result is documented as a fixture/configuration limitation rather
than hidden. The second is a release-blocking product defect fixed before the
stable version.

## Defect remediation

| Evidence | Commits | Result |
| --- | --- | --- |
| Semantic-invalid update and apply RED | `fa05bc7` | Reproduced |
| Real Mihomo staged validation | `2ac52e2` | GREEN |

| Restart-loop false-positive RED | `35a7fff` | Reproduced |
| `NRestarts` stability verification | `eb601a1` | GREEN |

The fixed behavior validates staged YAML with the installed Mihomo core before
replacement. After restart it requires the service to remain active without
increasing `NRestarts`; otherwise it stops the failed service, restores the
root-owned backup atomically, resets the failed unit, restarts the old config,
and returns a non-zero result.
